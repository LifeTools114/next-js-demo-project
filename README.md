# 쿠팡 하노이 직구 도우미

쿠팡 상품 페이지에서 **하노이 도착 가격**을 바로 보여주는 크롬 확장프로그램과,
주문·정산을 처리하는 백엔드입니다.

```bash
npm install
npm run build:ext   # 확장용 계산 로직 번들
npm run dev         # 백엔드 http://localhost:3000
npm test            # 로직 테스트 160개
npm run pack:ext    # 웹스토어 업로드용 zip
```

확장 설치: 크롬 `chrome://extensions` → 개발자 모드 → **압축해제된 확장 프로그램을 로드** → `extension/` 선택

**운영 방법은 [docs/OPERATIONS.md](docs/OPERATIONS.md)** — 하루 5분 동선, 설정 체크리스트, 검토 큐 대응.

---

## 1. 왜 확장프로그램인가

처음에는 자체 쇼핑몰로 만들었지만, 확장 방식이 근본적으로 낫습니다.

**쿠팡 파트너스 API 의 두 관문이 사라집니다.** 파트너스 API 키는 제휴링크 누적 판매
15만원을 채워야 나오는데(닭-달걀 문제), 확장은 **사용자가 이미 자기 브라우저에 띄운
페이지를 읽으므로** API 자체가 필요 없습니다. 서버 스크래핑도, 해외 IP 차단도 없습니다.

덤으로:

| | 자체 쇼핑몰 | 크롬 확장 |
|---|---|---|
| 가격 정확도 | API 스냅샷 + 10분 캐시 | **페이지 그 자체** (와우할인·쿠폰 반영) |
| 카탈로그 | 수집·분류·검수 필요 | 쿠팡이 곧 카탈로그 |
| 취급 품목 | 수집한 것만 | 쿠팡 전체 |
| 파트너스 약관 | 제휴 데이터를 자체 카탈로그로 사용 (리스크) | 트래픽을 쿠팡으로 보냄 (본래 용도) |

## 2. 이용 방식 두 가지

```
┌ 배송대행 (forwarding) ── 고객이 쿠팡에서 직접 결제
│   청구액 = 국제배송비 + 관세 + VAT
│   상품가는 청구하지 않지만 관세 과세표준(CIF)에는 포함됩니다.
│   수익: 배송 마진 + 쿠팡 파트너스 제휴 수수료
│
└ 구매대행 (agent) ── 당사가 대신 결제 (한국 카드·주소가 없는 고객)
    청구액 = 상품가 + 대행수수료 10% + 국제배송비 + 관세 + VAT
    수익: 대행수수료 + 배송 마진
```

### ⚠️ 제휴 수수료는 배송대행에서만 발생합니다

파트너스는 **본인 구매에 수수료를 지급하지 않습니다.** 구매대행은 당사가 사는
구조라 자기 구매(self-referral)로 잡히며, 제휴 링크를 붙이면 수수료도 못 받고
계정 제재 사유가 될 수 있습니다. 그래서 `config/affiliate.js` 가 트랙별로 적용
여부를 강제하고, `lib/coupang/deeplink.js` 는 구매대행 요청을 거부합니다.

규모는 상품가의 최대 3%(뷰티·패션 ~3%, 식품·생필품 ~2%, 가전 ~1%)이고
클릭 후 24시간 내 구매만 인정됩니다. 배송대행은 배송비만 받아 마진이 얇으므로
이 수수료가 실질적인 보완이 됩니다.

### 크롬 웹스토어 정책 준수

정책이 금지하는 것은 제휴 링크 자체가 아니라 **① 사용자 이익 없이 ② 고지 없이
③ 사용자 행동 없이** 삽입하는 행위입니다. 그래서:

- 페이지 로드 시 **URL 을 절대 건드리지 않습니다.** 버튼을 눌렀을 때만 제휴 링크를 생성합니다.
- 링크 옆에 고지 문구를 항상 표시합니다.
- 견적·통관 판정이라는 실질 서비스를 제공합니다.

## 4. 무게 산정

쿠팡 상품 페이지에는 배송 무게가 없고 **내용물 용량(50ml)** 만 있습니다.
실제 운임은 `내용물 + 용기 + 포장` 으로 매겨집니다.

```
"토리든 다이브인 세럼 50ml"  + 고시정보 "50ml"
  → 제형 판별 : 앰플/세럼 (밀도 1.03 g/ml)
  → 내용물    : 50 × 1.03      =  51.5g
  → 용기 공차  : 아크릴 펌프용기  =  68.1g
  → 완충재                     =  12.0g
  → 실무게                     = 131.6g   (실측 130g, +1%)
  → + 박스 250g → 청구 0.5kg → $4.5
```

제형 46종 · 용기 28종 테이블(`lib/weight/density.js`)로 화장품·식품·생활용품을
모두 다룹니다. 참고 제품 대비 화장품 ±2%, 식품 ±10% 수준입니다.

### 고시정보 우선 사용

상세페이지의 **내용물의 용량 또는 중량** 표는 상품명보다 정확하므로 `specOverride`
로 넘겨 우선 적용합니다. 단, `"600g (120g x 5)"` 처럼 **총량** 이 적힌 경우
상품명의 `"5개입"` 을 다시 곱하면 5배로 부풀려지므로, 고시정보에 수량 표기가 있으면
구성 수량을 1로 둡니다. (`test/weight.test.js` 가 이를 고정합니다)

## 5. 배송 가능 여부 — "문제되는 건 아예 차단"

세금이 특별히 붙거나 통관에 문제가 되는 품목은 복잡한 예외 계산 없이 **배송 불가**로
처리합니다. 고객이 결제한 뒤 창고에서 반송되는 것이 가장 큰 손실이기 때문입니다.

향수·주류·담배·의약품·축산물·씨앗·배터리·대형가전 등 **9개 유형 210개 키워드**로
주문 전에 차단합니다.

### ⚠️ 한국어 substring 오탐 — 이 프로젝트에서 가장 위험했던 버그

한국어에는 단어 경계가 없어 짧은 차단 키워드가 무관한 상품명에 우연히 포함됩니다.
초기 구현은 **정상 상품 21건 중 19건을 잘못 차단**했습니다.

| 차단 키워드 | 잘못 걸린 정상 상품 |
|---|---|
| `럼` (주류) | 히알루론산 **세럼** |
| `무기` (무기류) | **무기**자차 선크림, 칼슘**무기**질 |
| `회` (생선회) | **회**복 앰플, 기**회**, **회**전 브러시 |
| `릴` / `글로` | **릴**리즈 크림, 메쉬**글로**우 쿠션 |
| `라이터` | 하이**라이터** |
| `액상` / `연초` | **액상**형 클렌저, **연초**에 나온 신상 |

두 겹으로 막습니다.
1. 키워드를 오탐이 나지 않을 만큼 구체적으로 작성 (**1자 키워드 금지** — 테스트가 강제)
2. `SAFE_TERMS` 를 먼저 제거한 뒤 매칭

`test/eligibility.test.js` 의 정상 상품 코퍼스 37건 / 차단 대상 16건이 양방향을
고정합니다. **차단 키워드를 추가할 때는 반드시 이 테스트를 통과시키세요.**

## 6. 요금과 세금

```
배송비 = $9/kg × 청구무게
청구무게 = max(실무게, 부피무게) 를 0.5kg 단위로 올림, 최소 0.5kg
부피무게 = 가로×세로×높이(cm) ÷ 6000
```

지역 할증: 하노이 시내 $0 / 외곽 $3 / 근교 $7

### 품목군별 관세

"세금이 더 붙는 품목"을 단일 세율로 뭉뚱그리지 않습니다.

| 품목군 | 관세율 | | 품목군 | 관세율 |
|---|---|---|---|---|
| 신발 | 30% | | 주방·생활 | 15% |
| 가방·잡화 | 25% | | 유아·전자 | 10% |
| 의류·화장품·가공식품 | 20% | | 도서·문구 | 5% |
| 건강기능식품 | 15% | | 판별 실패 | 10% (기본) |

국제운임은 세관 관행대로 **가액 비례**로 각 품목에 배분한 뒤 품목별 CIF 에
품목별 세율을 적용합니다. VAT 10%는 (CIF + 관세) 에 부과됩니다.

> ⚠️ 베트남은 `Decision 01/2025/QD-TTg` 로 **2025-02-18 부터 소액 면세가 폐지**되어
> 금액과 무관하게 전 건 과세됩니다.
>
> ⚠️ 위 세율은 **추정값**입니다. 실제 세율은 HS 코드·원산지증명(VKFTA)·세관 판단에
> 따라 달라지므로 **운영 전 관세사 검토가 필수**이며, 최종 금액은 실납부액으로 정산합니다.

### 합배송

한국 창고에 따로 도착한 주문을 묶어 한 박스로 보냅니다. 절감은 세 곳에서 나오고,
보통 3번이 가장 큽니다.

1. 박스 무게 250g 을 건당이 아니라 1회만 가산
2. 최소 청구무게 0.5kg 를 1회만 적용
3. **0.5kg 올림 손실이 건별이 아니라 1회만 발생**

예) 0.6kg 3건 → 개별 3.0kg($27) vs 합배송 1.5kg + 취급비($15.5) = **43% 절감**

## 7. 결제 — 두 개의 별개 거래

```
[거래 A]  고객 ──VND──▶ 당사     선결제
[거래 B]  당사 ──KRW──▶ 쿠팡     구매대행일 때만
```

원장을 분리해 기록합니다. 고객이 낸 돈의 대부분(상품가·관세·VAT)은 매출이 아니라
고객 돈을 대신 지불하는 **예수금**이기 때문입니다. 총액으로 인식하면 매출이
9배 이상 부풀려집니다. 자세한 내용은 `lib/order/ledger.js` 참조.

주문 상태 머신은 허용되지 않은 전이를 서버에서 거부합니다(HTTP 409) — 결제 확인 없는
매입 착수, 매입 후 자동 취소를 막습니다.

**고객 뷰에는 매입 원가·마진·쿠팡 주문번호·운영자 계정이 절대 노출되지 않습니다.**
원장 항목을 화이트리스트로 투영하며 `test/order.test.js` 가 이를 고정합니다.

## 8. DOM 추출의 취약성

이 확장에서 가장 취약한 부분입니다. 쿠팡이 마크업을 바꾸면 깨집니다.

네 단계로 시도하고 앞 단계일수록 변경에 강합니다.

1. **JSON-LD** (schema.org Product) — SEO 용이라 잘 안 바뀝니다
2. **OpenGraph meta**
3. **CSS 셀렉터** — `/api/extension/config` 로 원격 갱신 (확장 재배포 불필요)
4. **실패** — 추측하지 않고 "읽을 수 없음"을 표시

> **원칙: 잘못된 견적은 침묵보다 나쁩니다.** 가격이나 상품명을 못 읽으면
> 엉뚱한 숫자를 만들어내지 않고 계산을 중단합니다.

MV3 는 원격 코드 실행을 금지하므로, 백엔드에서 받는 것은 **설정 데이터**(요율·세율·
셀렉터 문자열)뿐이며 코드는 확장에 번들되어 있습니다. 백엔드가 죽어도 확장은
번들된 기본 정책으로 계속 동작합니다.

## 9. 알려진 제약

| 항목 | 내용 |
|---|---|
| 주문 저장소 | 인메모리입니다. `lib/order/store.js` 의 읽기/쓰기를 DB로 교체해야 합니다 (상태 머신·원장·정산 로직은 그대로 재사용) |
| DOM 셀렉터 | 쿠팡 개편 시 깨집니다. `/api/extension/config` 의 `SELECTORS` 로 대응하되, 실제 쿠팡 페이지로 주기 점검이 필요합니다 |
| 세율 | 관세사 검토 전까지는 가정값입니다 |
| 무게 | 세트·기획 구성처럼 규격이 없는 상품은 오차가 커집니다 (신뢰도 `낮음` 표기) |
| 전자지갑 | MoMo/ZaloPay/VNPay 는 어댑터 골격만 있습니다 |
| 운영자 인증 | 단일 토큰 방식입니다. 프로덕션에서는 세션/OAuth 로 교체하세요 |
| 확대 | 현재 베트남 전용입니다. 다른 국가는 `config/eligibility.js` 와 `config/taxes.js` 를 국가별로 분리해야 합니다 |
