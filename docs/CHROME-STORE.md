# 크롬 웹스토어 등록 자료

> 이 문서 하나만 보고 등록 양식을 채울 수 있게 정리했습니다.
> 값이 바뀌면(이름·설명·권한) **여기와 `extension/manifest.json` 을 함께** 고치세요.

---

## 0. 등록 전 체크 — 왜 이렇게 만들었나

크롬 웹스토어에서 확장이 내려가는 이유는 대개 셋입니다.

| 위험 | 우리가 한 것 |
|---|---|
| 남의 서비스를 **사칭** | 이름·배너에서 다른 회사 상표를 모두 뺐습니다. 우리 이름은 「베트남 직구 도우미」 |
| 남의 화면을 **대신 조작** | 클릭·자동입력을 전부 삭제했습니다. 읽어서 보여주고, 값은 복사만 합니다 |
| **하는 일이 여러 개**(단일 목적 위반) | 하는 일은 하나입니다 — *한국 온라인몰 상품의 베트남 도착 가격 계산과 배송지 입력 안내* |

테스트로 고정해 둔 것 (`npm test`)
- `확장은 쇼핑몰 화면을 조작하지 않는다` — `.click()` · `dispatchEvent` · `.value =` 가 콘텐츠 스크립트에 있으면 실패
- `자동 클릭·자동 채우기는 코드에 남아 있지 않다`
- `제휴(파트너스) 연동은 코드에 남아 있지 않다`
- `남의 브랜드 이름을 배너에 쓰면 안 됩니다`
- `고객에게 보이는 글에는 남의 상호를 쓰지 않는다` — 정규식(화면 글자 인식) 밖에 상호가 있으면 실패

## 1. 기본 정보 (양식에 그대로 붙여넣기)

| 항목 | 값 |
|---|---|
| 이름 | 베트남 직구 도우미 |
| 짧은 설명 (132자 이내) | 한국 온라인몰 상품의 베트남 도착 예상 가격을 계산하고, 배송지 입력 방법을 안내합니다. 화면을 대신 조작하지 않습니다. |
| 카테고리 | 쇼핑 (Shopping) |
| 언어 | 한국어 (기본), 베트남어 추가 가능 |
| 개인정보 처리방침 URL | `https://<도메인>/privacy` |
| 지원 이메일 | 운영자 이메일 |

### 자세한 설명 (Description)

```
베트남에서 한국 물건을 살 때, 베트남(북부) 문 앞까지 얼마가 드는지 미리 알려드립니다.

■ 이런 분께
· 한국 온라인몰에서 물건을 사서 베트남(북부)으로 받고 싶은 분
· 배송비까지 합쳐 얼마인지 사기 전에 알고 싶은 분

■ 하는 일
· 상품 화면에서 도착 예상 가격 계산 (무게 추정 → 국제배송비 → 총액, 원화·동화)
· 보낼 수 없는 물건(항공 금지품·냉장/냉동 식품 등) 미리 알림
· 한국 창고 배송지 입력 방법 안내 — 값은 버튼 하나로 복사

■ 하지 않는 일
· 쇼핑몰 화면을 대신 누르거나 채우지 않습니다. 모든 입력은 고객이 직접 하십니다.
· 로그인·결제 정보를 읽지 않습니다.
· 계산은 브라우저 안에서 합니다. 신청서를 여시기 전에는 아무것도 서버로 보내지 않습니다.

■ 필요한 권한
· storage — 견적함과 설정을 이 브라우저에만 저장합니다.
· 쇼핑몰 페이지 접근 — 보고 계신 상품의 이름·가격·수량을 읽어 계산합니다.
```

## 2. 권한 사용 사유 (심사에서 반드시 물어봅니다)

`manifest.json` 의 값과 1:1로 답을 맞춰 두었습니다.

| 권한 | 왜 필요한가 (양식에 적을 말) |
|---|---|
| `storage` | 고객이 담아둔 상품 목록과 켜짐/꺼짐 설정을 이 브라우저에만 저장합니다. 서버로 보내지 않습니다. |
| 쇼핑몰 도메인 host 권한 | 상품 화면에서 **상품명·가격·수량**을 읽어 도착 가격을 계산하고, 결제 화면에서 배송지가 창고 주소인지 확인해 안내하기 위해서입니다. 페이지를 수정하지 않습니다. |
| 자사 도메인 host 권한 | 견적 계산에 쓰는 요율·창고 주소 설정을 내려받고, 고객이 [신청서 열기]를 누르면 신청 화면을 엽니다. |

> ⚠️ **등록 전에 확인**: `host_permissions` 의 `http://localhost:3000/*` 는 개발용입니다.
> 스토어에 올릴 zip 에서는 빼고, 자사 도메인만 남기세요. (남겨두면 심사에서 사유를 묻습니다)

### 원격 코드 실행 금지 (MV3)
- 외부에서 **코드**를 받아 실행하지 않습니다. 서버에서 받는 것은 **값**뿐입니다
  (요율·창고 주소·화면 문구 목록). 문구는 확장 안에서 `RegExp` 로 컴파일하며,
  길이·컴파일·속도 검사를 통과하지 못하면 무시하고 번들 기본값을 씁니다.
- `eval`·`new Function`·원격 스크립트 태그를 쓰지 않습니다.

## 4. 올릴 파일

### 확장 zip 만들기 — `npm run pack:store` 한 줄

```
npm run build:ext
npm run pack:store
```
기본 서버 주소는 `https://naka.1dollartool.com` 입니다. 다른 서버로 만들 때만
`STORE_BACKEND_URL=https://<주소> npm run pack:store`
(윈도우 PowerShell: `$env:STORE_BACKEND_URL="https://<주소>"; npm run pack:store`).

결과: `dist/vietnam-helper-<버전>.zip`. 이 명령이 대신 해주는 것:
- `host_permissions` 에서 개발용 `http://localhost:3000/*` 제거
- 확장이 붙는 기본 서버 주소(`DEFAULT_BACKEND`)를 `https://naka.1dollartool.com`(또는 `STORE_BACKEND_URL`)로 교체
  (https 여야 하고 `manifest.json` 의 host_permissions 에 있는 도메인이어야 합니다 — 아니면 중단)
- 번들(`vendor/calc.js`)이 소스와 같은지 확인

> ⚠️ **사이트가 먼저 공개 서버에 떠 있어야 합니다.** 확장은 그 서버에서 요율·창고 주소를 받고,
> 스토어 등록 양식의 개인정보 처리방침 URL(`https://naka.1dollartool.com/privacy`)도 심사관이 실제로 엽니다.
> localhost 로는 등록할 수 없습니다.

포함되는 것: `manifest.json`, `_locales/`, `icons/`, `src/`, `vendor/calc.js`

### 이미지
| 종류 | 규격 | 상태 |
|---|---|---|
| 아이콘 | 128×128 PNG | `extension/icons/128.png` ✅ (파란 바탕 + 노란 별 — 배너와 같은 색) |
| 스크린샷 | 1280×800 또는 640×400, 최소 1장(최대 5장) | **준비 필요** |
| 작은 홍보 타일 | 440×280 | 선택 |

스크린샷으로 쓸 화면 (권장 4장)
1. 상품 화면의 도착 가격 패널 (배송만 / 구매하고 배송까지 두 줄)
2. 시작 배너 — 「신청」 누르기 전 상태
3. 배송지 입력 안내 + [복사] 버튼
4. 보낼 수 없는 물건 안내 (냉장·냉동 식품 등)

## 5. 심사에서 자주 묻는 것 — 미리 준비한 답

**Q. 단일 목적이 무엇입니까?**
> 한국 온라인몰 상품의 베트남 도착 예상 가격을 계산해 보여주고, 한국 창고 배송지 입력 방법을 안내하는 것입니다.

**Q. 왜 여러 도메인에 접근합니까?**
> 상품 화면·장바구니·결제 화면의 주소가 서로 달라서입니다. 하는 일은 모두 같습니다 — 읽어서 계산하고 안내합니다.

**Q. 페이지를 수정합니까?**
> 우리 안내 카드를 화면 오른쪽 아래에 추가하는 것뿐입니다(우리 요소에는 `data-kb-ui` 표시가 있습니다).
> 쇼핑몰의 버튼을 누르거나 입력칸을 채우지 않습니다.

**Q. 제휴(어필리에이트) 링크를 넣습니까?**
> 넣지 않습니다. 관련 코드를 모두 삭제했고 테스트로 막아 두었습니다.

**Q. 상품 페이지를 다시 내려받는 코드(`fetch(location.href)`)는 무엇입니까?**
> 색상·용량 옵션을 바꾸면 주소만 바뀌고 화면은 새로 그려지지 않아, 처음 실린
> 구조화 데이터(JSON-LD)가 옛 값으로 남습니다. 그래서 **지금 보고 있는 그 주소**를
> 한 번 더 받아 구조화 데이터만 갈아끼웁니다. 다른 주소는 부르지 않고, 받은 내용을
> 밖으로 보내지도 않습니다. (`extension/src/content/main.js` `refetchStructuredData`)

**Q. 결제 버튼을 가로챕니까?**
> 누르거나 막지 않습니다. 배송지가 한국 창고가 아닌 채로 [결제하기]를 누르면
> 브라우저 확인창(`confirm`)으로 "이대로 결제하면 베트남이 아니라 현재 배송지로
> 갑니다"라고 한 번 묻습니다. [확인]이면 그대로 진행되고, [취소]는 **고객이 고른**
> 것입니다. 물건이 엉뚱한 곳으로 가는 것을 막는 마지막 확인이며, 카드를 닫으면
> 이 확인도 꺼집니다. (`extension/src/content/order-capture.js` `armPayGuard`)

## 6. 등록 뒤 관리

- 고객 흐름 시험은 **처음 설치한 상태**에서: 확장 팝업 [설정] 탭 → **[🧹 모두 지우기]** (견적함·설정·
  운영자 토큰이 지워지고 서버 주소만 남음) → 쿠팡 탭을 모두 닫고 새로 엽니다. 운영자 토큰이 남아 있으면
  결제 완료 화면이 고객용 카드 대신 운영자용(매입 기록)으로 동작합니다.

- 버전 올리기: `extension/manifest.json` 의 `version` → `npm run pack:store` → 대시보드에 새 버전 업로드 → 심사
- 화면 문구가 바뀌어 계산이 멈추면: 서버의 `config/coupang-patterns.js` 값만 고치면
  확장 재배포 없이 반영됩니다 (값만 내려갑니다 — 코드가 아닙니다)
- 개인정보 처리방침을 고치면 `pages/privacy.js` 와 스토어의 URL 내용이 같아야 합니다
