## 1. 서비스 개요

| 항목 | 내용 |
|---|---|
| 하는 일 | 한국 쇼핑몰(현재 쿠팡)에서 산 물건을 **베트남 북부**까지 항공특송으로 보내고, 한국 결제수단이 없는 고객은 **대신 사서** 보냅니다. |
| 두 가지 방식 | **📦 배송만**(정식 용어 배송대행) — 고객이 직접 결제, 배송지는 한국 창고, 우리는 배송비만 받음. **🛒 구매하고 배송까지**(구매대행) — 고객은 링크·개수만, 우리가 대신 사서 상품값+수수료+배송비를 한 번에 받음. 코드 id 는 `forwarding` / `agent` (절대 바꾸지 않음 — 저장된 주문이 이 값을 물고 있음). |
| 배송 지역 | 하노이 시내·빈푹·박닌·박장·흥옌·하이즈엉·하이퐁 (베트남 북부). 중부·남부는 배송하지 않음. 목록에 없는 도시는 접수 불가. |
| 고객 접점 | 폰 웹(링크 하나로 시작) · PC 크롬 확장(쿠팡 화면 위 가격 카드) · 웹 신청서 · 주문 조회 · 카카오톡 문의 |
| 운영자 접점 | `/admin`(검토 큐·발주·입고·정산·고객·백업·대신 읽기 상태) · `/admin/intake`(창고 입고) · 텔레그램(물류사 연동) |
| 기본 원칙 | ① 잘못된 금액은 침묵보다 나쁘다 — 못 읽으면 실패로 표시하고 추측하지 않는다. ② 주문은 생성 시점 견적을 **동결**한다. ③ 고객 화면·확장에는 원가·마진·남의 상호를 넣지 않는다. ④ 쇼핑몰 화면을 **읽기만** 하고 클릭·자동입력 하지 않는다. ⑤ 쉬운 말(배송만/구매하고 배송까지)을 쓰고 정식 용어는 문서에만 병기한다. |

## 2. 구성 (아키텍처)

### 2.1 한눈에

```
[고객 폰/PC 브라우저] ── https ──▶ [Next.js 서버 (Vultr, Ubuntu 24.04, Caddy HTTPS)] ──▶ .data/*.json (파일 저장)
        │                                   ▲            │
        │ (PC) 크롬 확장 ── 쿠팡 화면 읽기 ──┘            ├─▶ 텔레그램(물류사·운영자 알림)
        │                                                └─▶ 환율 자동 갱신
[사장님 PC 크롬 확장 「대신 읽기」]  또는  [서버 크롬 kb-worker]  ── 3초마다 작업 가져가 쿠팡 상품 화면을 열어 읽음 ──▶ 서버
```

### 2.6 대신 읽기 (링크 → 이름·옵션·가격 자동)

쿠팡은 서버(데이터센터) 접속을 봇 차단으로 막으므로(PC 403·폰 검사 페이지·브랜드관 Access Denied), 서버는 **링크 풀기**(짧은 링크 → 상품 번호·정식 주소)까지만 하고 **화면 읽기는 진짜 브라우저**가 합니다. §6 참고.

### 3.2 구매대행 수수료 (배송만에는 없음)

수수료 = **기본 3,000원**(상품가 합계 10만원·5종류까지) + 10만원 초과분 × **5%** + 5종류 초과 시 종류당 **1,000원**.
1회 접수 상한 상품가 합계 **100만원**(넘으면 나눠서). 국내 배송비(판매자→창고)는 구매대행에서만 화면에서 읽은 값 그대로(못 읽으면 0, 상한 5만원). 결제대행 수수료 0(계좌이체뿐). 최소 주문 금액 0(비활성, 값만 넣으면 살아남).

### 3.4 합배송·보관·반송

- 합배송: 무료 보관 **30일**, 이후 $0.5/일, 한 소포 최대 20건, 합포장 취급 $2.
- 반송(하노이→한국): 기본 $20(2kg) + kg당 $11, 구매대행 처리비 5,000원. 액체·배터리 내장·현금·카드·대량은 반송 불가. 사전 접수 필수.
- 보관 기간 경과 시 반송 또는 폐기(고지).

### 3.5 환율·통화

- 모든 금액의 원천은 **KRW**. VND 표시는 주문에 고정된 환율로 환산(1,000동 단위 반올림). 접수 시점 환율 **고정**(lockFxAtOrder).
- 기본 KRW→VND 18.5, USD→KRW 1,380, 스프레드 1.5%. 서버가 주기적으로 자동 갱신(`FX_REFRESH_HOURS`), 운영자가 `/admin` 에서 수동 설정 가능.

### 3.6 세금

- 현재 **관세·VAT 미징수**(`TAXES.collect=false`) — 수하인 부담으로 고지. 켜면 품목군별 관세율 표(신발 30%, 가방 25%, 의류·화장품·가공식품 20%, 건강기능식품·주방 15%, 유아·기기·전자 10%, 도서 5%, 기본 10%)와 VAT 10% 로 계산.
- 자가 사용: 동일 상품 5개 초과·총액 500만동 초과 시 경고.

### 3.8 무게 산정 (상품명 기반 추정)

내용물 = 용량(ml)×밀도, 용기 = base + ratio×내용물(용기 테이블), 실무게 = (내용물+용기+완충재)×수량, 부피무게 = 박스 부피÷6000, 청구무게 = max. 고시정보 표(용량·중량)가 있으면 우선. 결과에는 항상 신뢰도(high/medium/low)와 근거가 붙고, 고객에게 「추정치」임을 표시. 화면 값이 옵션 최저가(AggregateOffer)면 확정값으로 쓰지 않음.

### 3.9 주문 상태 머신

`REQUESTED 주문 접수 → AWAITING_PAYMENT 입금 대기 → PAID 결제 완료 → PURCHASING 한국 구매 중 → PURCHASED 구매 완료 → IN_WAREHOUSE 창고 입고·실측 → SETTLEMENT_DUE 차액 정산 대기 → SETTLED 정산 완료 → SHIPPED 국제배송 중 → DELIVERED 배송 완료`, 어디서든 `CANCELLED 취소`.
- 입고 실측이 등록되면 정산까지 **자동 연쇄**(차액이 허용오차 안이면 정산 불필요로 바로 SETTLED).
- 상태가 바뀔 때마다 알림 원장 기록 + 운영자 웹훅(고객 채널은 어댑터만 추가).
- 주문번호 `HN` + 연월일 + 순번(예 HN2609120001). 순번이라 추측이 쉬우므로 접근 규칙(§3.11)이 필요.

## 4. 화면 흐름

**화면 뼈대**: 어느 화면이든 아래 5탭(🛒 신청 · 📊 요금 · 📦 내 신청 · 📖 안내 · 👤 마이)으로 오가고, 위에는 「📋 이용약관」과 배송 가능 지역 바가 항상 보인다. 신청 흐름은 단계 표시 ①상품 → ②견적 → ③받는 분 → ④완료 를 따라간다.
**폰 고객**: 쿠팡 앱에서 상품 → 공유 → 링크 복사 → 우리 사이트 「🔗 쿠팡 상품 링크 붙여넣기」 → `/send` 에 링크 → (대신 읽기) 이름·옵션·가격·용량 채워짐 → 옵션 칩 고르면 그 옵션 가격으로 → 개수 → 「얼마인지 보기」 → 신청서 → 필수 동의 → 접수 → 입금 안내 → 상태 조회. 대신 읽기가 없으면 가격만 직접 적음.
**배송만(폰)**: 창고 주소를 한 항목씩 복사(상세주소 「YS-ECOM 이름」 필수) → 쿠팡에서 결제 → 돌아와 상품 링크 → 배송비 → 신청서.
**PC 고객(확장)**: 쿠팡 상품 화면 배너 → 켜기 → 도착 가격 카드(두 방식) → 담아두기/신청 → 결제 화면 배송지 안내(복사·확인창) → 주문완료 화면 「결제 완료 → 신청서」 카드(주문번호 자동 연결).
**운영자**: `/admin` 검토 큐 → 입금 확인 → 발주(확장 [운영] 탭 「상품 탭 열기」, 매입 자동 기록) → 창고 입고·실측(`/admin/intake`, 수령인 코드로 자동 매칭) → 정산 자동 → 매니페스트 생성·물류사 텔레그램 발송 → 배송 완료.

## 5. 확장 규정 (스토어 심사 대응)

- 남의 상호·제휴 문구 없음(테스트).
