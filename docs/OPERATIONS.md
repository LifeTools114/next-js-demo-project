# 운영 가이드 — 하루 5분 동선

이 시스템의 설계 목표는 하나입니다: **운영자가 주문마다 하는 디지털 작업을
"무게 입력 1번"(배송대행) / "쿠팡 결제 클릭 + 무게 입력"(구매대행)까지 줄이는 것.**
나머지는 자동입니다. 이 문서는 그 자동을 전제로 한 실제 동선입니다.

## 0. 서버 켜기 — 명령 하나

**가장 쉬운 방법**: 저장소 폴더의 **`start-server.cmd` 를 더블클릭**하세요.
최신 코드 받기 → 패키지 확인 → 설정 확인 → 이전 서버 정리 → 시작 →
관리자 화면 자동 열기까지 한 번에 합니다.

PowerShell 에서 직접 하려면:

```powershell
cd C:\Users\acma2\next-js-demo-project
.\scripts\start-server.ps1
```

스크립트 없이 손으로 할 때는 이렇게 씁니다. **PowerShell 은 `&&` 를 쓰지
못합니다** — 여러 명령을 한 줄에 이을 때는 세미콜론(`;`)입니다.

```powershell
cd C:\Users\acma2\next-js-demo-project ; git pull ; npm run dev
```

> `'&&' 토큰은 이 버전에서 올바른 문 구분 기호가 아닙니다` 오류가 그 이유입니다.

서버를 끌 때는 그 창에서 **Ctrl+C**. 포트 3000 이 이미 잡혀 있으면
`start-server.cmd` 가 알아서 이전 서버를 정리하고 새로 띄웁니다.

## 0-1. 공개 도메인으로 옮길 때 (1dollartool.com 서브도메인)

고객이 쓰려면 백엔드가 인터넷에 있어야 합니다. `localhost` 는 사장님 PC 안에서만
보입니다. 자사 도메인의 **서브도메인**을 쓰면 됩니다 (예: `hanoi.1dollartool.com`).

바꿀 곳은 세 군데뿐입니다.

1. **서버 배포** — 그 서브도메인이 이 Next.js 앱을 가리키게 하고 **HTTPS** 로 엽니다.
2. **확장 설정** — 확장 팝업 아래 [백엔드 주소] 칸에 `https://hanoi.1dollartool.com`
   을 넣습니다. (도메인을 바꾸면 설정 캐시가 자동으로 비워져 바로 반영됩니다.
   `manifest.json` 의 `host_permissions` 에 `https://*.1dollartool.com/*` 가
   이미 들어 있어 어떤 서브도메인이든 됩니다.)
3. **환경변수** — `.env.local` 에 `BASE_URL=https://hanoi.1dollartool.com`.
   알림 문구의 관리자 링크가 이 주소로 나갑니다.

**공개 서버에서는 `ADMIN_TOKEN` 이 반드시 있어야 합니다.** 없으면 운영자 API 가
전부 차단됩니다(그게 안전 장치입니다). `/admin` 은 인터넷에서 접근 가능해지므로
토큰을 반드시 채우세요.

## 1. 하루 동선

### 고객이 겪는 흐름 (배송대행 기본 — 쿠팡 결제가 먼저)

1. 쿠팡에서 **고객이 직접 결제** — 확장 패널이 결제 전에 한국 창고 주소를 보여줌
2. 주문완료 화면에서 확장이 **[하노이 배송 신청]** 버튼을 띄움 →
   누르면 쿠팡 주문번호가 자동 연결된 채 배송비 청구서(체크아웃)로 이어짐
3. 고객이 배송비 입금 → 운영자가 콘솔에서 **[입금 확인]** (§아침) →
   이후 "창고로 배송 중"까지 자동 진행

> 입금 확인은 **지금은 수동이 기본**입니다 (은행 앱 대조 후 버튼 한 번).
> 입금 웹훅 서비스를 연결하면(§3) 이 단계도 자동으로 바뀌고,
> 수동 버튼은 예외 처리용으로 남습니다.

### 아침 — 콘솔 확인 (1~2분)
`/admin` 접속:

- **입금 대기 주문** — 은행 앱과 대조해 [입금 확인]. 쿠팡 주문이 이미
  연결된 배송대행은 이 클릭 한 번으로 창고 대기까지 자동 진행됩니다.
- **검토 필요** 패널 — 자동화가 처리하지 못한 것만 여기 옵니다.
  비어 있으면 볼 것이 없습니다. (대응법은 §4)
- 발주 대기(구매대행 PAID)가 있으면 → 확장 팝업 **운영 탭**에서 처리 (§2)

### 소포 도착 — 입고 (소포당 ~20초)
`/admin/intake` (폰 브라우저 권장):

1. 라벨의 **세부주소 코드(YS-ECOM(이름)) / 쿠팡 주문번호 / 운송장** 아무거나 스캔·붙여넣기
2. 주문이 뜨면 저울 무게(g) 입력 → **[실측 등록 → 자동 정산]**
3. 끝. 차액 없으면 정산 완료까지 자동, 차액이 있으면 고객 청구/환불이
   자동 기록되고 알림이 남습니다.

- 연결 안 된 배송대행 소포(입금만 된 상태)는 그 자리에서 운송장 입력
  한 번으로 연결됩니다.
- 해외직구 상품 포함 주문은 실물·추가비용 확인 체크가 떠야 진행됩니다
  (정책상 사람 확인 필수 구간).

### 발송일 — 묶음 발송 (묶음당 ~1분)
`/admin` 의 **발송 준비** 패널:

1. 보낼 주문 체크 → **[매니페스트 CSV]** → 물류사에 전달
2. 물류사가 준 운송장(마스터 AWB) 입력 → **[일괄 발송]**
3. 전 주문이 한 번에 SHIPPED 처리되고 고객 알림이 기록됩니다.

### 도착·배달 확인 — 텔레그램 연동이면 자동
파트너가 텔레그램 방에 보내는 한 줄이 곧 처리입니다 (§2-1):
하노이 도착·배송일정·배달완료가 고객 주문 페이지의 **📍 내 물건 위치**에
그대로 반영되고, 배달완료는 주문 상태까지 닫습니다.
연동 전에는 콘솔에서 해당 주문 **[배송 완료]** 를 눌러주세요.

## 2. 구매대행 발주 (확장 운영 탭)

1. 확장 팝업 → **운영** 탭 → ADMIN_TOKEN 저장 (최초 1회)
2. 발주 대기 주문에서 **[발주 착수]** → **[상품 탭 열기]**
   (주문 상품 페이지가 탭으로 열리고, 각 페이지 패널에 "이 상품 N개" 힌트가 뜸)
3. 쿠팡 장바구니 담고 **결제** — 여기까지가 사람 일의 전부
4. 주문완료 화면에서 주문번호·결제액이 **자동 수집**되어 매입 기록까지 끝남
   - 자동 수집이 보류되면(동시 발주 여러 건 등) 팝업의 수동 기록 폼 사용

> 쿠팡 결제 자체는 의도적으로 자동화하지 않습니다 — 자동결제 봇은
> 약관 위반·계정 정지 위험이 있습니다.

### 발주 가격 원칙 — "고객이 본 가격 그대로"

고객은 화면에 표시된 가격(와우회원가·1개 판매가·다개 할인가)을 보고
신청합니다. 신청서의 상품가가 그 **가격 스냅샷**이고, 발주는 이 원칙을 따릅니다.

- **기본은 와우회원가**로 주문합니다. 상품 패널의 발주 힌트에
  **고객 표시가**가 함께 떠 있으니, 담기 전에 지금 가격이 그 금액(이하)인지
  확인하세요. 와우가 비적용 상품이면 가격이 다를 수 있습니다.
- **표시가보다 비싸졌으면 결제하지 마세요.** 결제해 버려도 자동 수집이
  표시가+3,500원(국내배송비 여유)을 넘는 결제는 **자동 기록을 거부**하고
  검토 큐(`over-price`)에 남깁니다 → 고객에게 차액 추가 입금 또는 취소·전액
  환불을 확인한 뒤 팝업에서 직접 기록하세요.
- **더 싸게 산 경우**(계정 쿠폰 자동 적용, 와우 가입 쿠폰 등)는 그대로
  진행합니다 — 차액은 원장에 음수로 남아 마진으로 집계됩니다. 계정에
  발급된 쿠폰은 운영자 자산이며, 고객 청구액은 바뀌지 않습니다.
  (쿠폰이 "결제 시 자동 적용"되는 유형이면 그냥 결제하면 됩니다)
- **마감임박·품절**이면 임의 대체 구매 금지 — 주문 취소 후 전액 환불이
  기본입니다. 신청서·주문 페이지에 이 원칙이 고객에게도 고지되어 있습니다.

### 국내 배송비 규정 (운영자 확정 26-09-06)

마켓플레이스 상품은 쿠팡 화면에 "배송비 3,000원" 이 따로 붙습니다.
구매대행은 **우리가 결제**하므로 이 돈도 우리 돈입니다 — 견적에 넣습니다.

| | 배송만 | 구매하고 배송까지 |
|---|---|---|
| 국내 배송비 | 안 걷음 (고객이 쿠팡에 직접) | 쿠팡 화면 금액 그대로 |

- **판매자마다 한 번**만 붙습니다. 같은 판매자 상품을 여러 개 담아도 한 번입니다.
- **"같은 판매자 상품 N원 이상 무료"** 는 그 판매자 상품 합계로 판정합니다.
  넘으면 0원이고 내역에서 줄이 아예 사라집니다.
- **화면에서 못 읽으면 걷지 않습니다.** 짐작으로 걷으면 무료배송 상품에도
  붙어 고객이 모르는 돈을 냅니다. 우리가 조금 손해 보는 쪽을 택합니다.
- 로켓배송은 와우회원 무료라 대개 0원입니다.

값을 바꿀 곳: `config/fees.js` `domesticShip` · 규정 본문 `lib/pricing/domestic.js`.
화면 읽기는 `extension/src/content/extract.js` `readDomesticShipping`.

## 2-1. 텔레그램 물류 파트너 연동

봇 하나가 파트너 방에서 양방향으로 움직입니다.

**받는 것 (파트너 → 시스템)** — 방에 한 줄씩 보내달라고 요청하세요:

| 파트너 메시지 예시 | 처리 |
|---|---|
| `YS-ECOM(박하노) 1.42kg` | 입고 + 실측 → 정산까지 자동, 봇이 처리 결과 회신 |
| `HN2609010001 하노이 도착` | 고객 위치 표시 "하노이 도착" |
| `배송일정 HN2609010001 9/3 오전` | 고객에게 "🚚 배달 예정: 9/3 오전" |
| `배달완료 HN2609010001` | 배송 완료 처리 |

식별자는 YS-ECOM(이름)·주문번호(HN…)·운송장 무엇이든 되고, 어순이 달라도
알아듣습니다. 처리 못 하면 봇이 이유를 회신하므로 파트너가 바로 압니다.

**보내는 것 (시스템 → 파트너)**: 콘솔에서 [일괄 발송] 하는 순간
적하목록 CSV + "📦 하노이행 N건 · AWB …" 가 파트너 방으로 자동 전송됩니다.

**설정 (1회)**:
1. 텔레그램 @BotFather → `/newbot` → 토큰 복사 → `TELEGRAM_BOT_TOKEN`
2. 봇을 파트너 방에 초대. 방에서 아무 메시지나 보낸 뒤
   `https://api.telegram.org/bot<토큰>/getUpdates` 를 열면 `chat.id` 가 보입니다
   (그룹은 음수) → `TELEGRAM_PARTNER_CHAT_ID`
3. `TELEGRAM_WEBHOOK_SECRET` 아무 긴 문자열, `BASE_URL` 서비스 주소 설정 후
   `npm run telegram:webhook` 실행
4. (선택) 운영자 알림도 받으려면 본인·직원 방 ID 를 `TELEGRAM_OPERATOR_CHAT_ID` 에

**안전**: 등록된 파트너 방의 메시지만 처리하고, 허용 액션은 물류 4종뿐입니다
(입금 확인·취소 등 돈 관련은 텔레그램으로 불가). 모든 수신·처리 내역은
`.data/telegram.jsonl` 에 남습니다.

## 3. 처음 한 번 설정 (env)

`.env.example` 를 `.env.local` 로 복사해 채우세요.

| 항목 | 변수 | 없으면 |
|---|---|---|
| 운영자 토큰 | `ADMIN_TOKEN` | 프로덕션에서 운영자 기능 차단 |
| VND 수금 계좌 | `VN_BANK_*` | 기본값 내장 (신한은행 베트남 700-032-202396 · 김영서 — 26-08-31 변경) |
| KRW 수금 계좌 | `KR_BANK_*` | 기본값 내장 (카카오뱅크 3333-02-2739576 · 김영서 — 26-08-31 변경) |
| 한국 창고 주소 | `KR_WAREHOUSE_*` | 확정값 내장 (개화동로 11길 5 · 세부주소 YS-ECOM(이름)) |
| 입금 자동확인 | `PAYMENT_WEBHOOK_TOKEN` | 웹훅 비활성 = 입금 수동 확인 |
| 운영자 알림 | `NOTIFY_WEBHOOK_URL` | 알림이 파일 기록만 됨 |
| 환율 | (자동) | API 실패 시 `NEXT_PUBLIC_*` 기본값 |

**입금 자동확인 연결**: 은행 입금 알림 서비스(베트남 Casso·SePay 계열,
한국 오픈뱅킹·가상계좌)에 가입하고, 알림 대상 URL 을
`https://<도메인>/api/payment/webhook?currency=VND` (KRW 계좌는 `?currency=KRW`)
+ 헤더 `X-Webhook-Token` 으로 등록하면 끝입니다. 고객이 이체 메모에 넣는
주문번호로 자동 대조되고, 실패 건만 검토 큐에 남습니다.

## 4. 검토 큐 대응표

| 표시 | 뜻 | 대응 |
|---|---|---|
| 이체 메모에 주문번호 없음 | 고객이 메모를 빠뜨림 | 은행 내역·금액으로 주문 찾아 콘솔 [입금 확인] |
| 부족 입금 | 청구액보다 적게 입금 | 고객에게 차액 안내 후 수동 확인 |
| 초과 입금 (확인은 완료) | 더 보냄 — 주문은 정상 진행됨 | 차액 환불 여부만 판단 |
| 결제 대기 상태 아님 | 같은 입금 알림 중복 등 | 대부분 무시 가능 |
| 쿠팡 캡처 보류 | 동시 발주 여러 건이라 자동 기록 안 함 | 팝업 발주 목록에서 해당 주문에 수동 기록 |

## 5. 외부가 확정되면 바꿀 곳 (각 한 줄)

| 확정되는 것 | 바꿀 곳 |
|---|---|
| 물류사 엑셀 양식 | `config/manifest.js` 컬럼 배열 |

### 발견해 고친 오차 (원인별)

1. **중량 앞 낱개 수를 구성 수량으로 곱함** — "캡슐 세제 55입, 440g, 2개"가
   440g×55 = 24.2kg 로 부풀어 접수가 막혔습니다. 쿠팡 표기는
   "규격(낱개 수), 총중량, 구성 수량" 순서라 중량 **뒤**의 수량만 구성
   수량으로 인정합니다.
2. **치수를 수량으로 오인** — "수건 40x80 10장"의 80, "포스트잇 76x76"의 76을
   구성 수량으로 곱해 9.9kg·20.9kg 이 나왔습니다. 치수 패턴을 먼저 제거합니다.
3. **부피무게 폭주** — 박스 부피를 개수만큼 통째로 곱해 화장지 30롤이 42kg.
   이제 "박스 기본 부피 1회 + 내용물 부피 × 개수"로 계산하고, 저밀도 품목의
   박스 계수를 현실화했습니다(밀도에 이미 부피가 반영돼 이중 계산이었음).
4. **미등록 품목이 화장품 80ml(0.12kg)로 과소평가** — 가전·신발·가구·완구·
   캐리어 등이 모두 0.12kg. 제형 40여 종을 추가하고, 상품명으로 못 찾으면
   **카테고리→제형 매핑**으로 받도록 안전망을 넣었습니다. 과소 견적은 곧
   손실이므로 이 항목이 가장 중요합니다.
5. **카테고리명이 제형을 덮어씀** — "스킨케어"의 '스킨'이 토너로,
   "아이스크림"의 '크림'이 유리단지로 잡혔습니다. 제형은 상품명 우선.
6. **단위 표기 미적용** — "10ml 30포", "18g 20매", "0.9g 100개입"을 총량으로
   보아 10g·18g 으로 계산했습니다. 이제 낱개 표기는 개수를 곱합니다.
7. **이중 수량** — "140g 5개입 4묶음" = 20개로 곱합니다.
8. **용기가 규모를 못 따라감** — 550g 크림에 50ml 유리단지 공차(690g)를
   적용했습니다. 내용물이 크면 큰 용기로 전환합니다.
9. **텀블러의 ml 은 내용물이 아님** — 빈 콜드컵 710ml 가 710g 이 됐습니다.
10. 키워드 오인 다수: 필**립**스→립스틱, 크**린스**틱→린스, **매직**컴포트
    기저귀→문구, 아이**패드**→토너패드, **인덕션** 냄비→대형가전,
    가전**액세서리**(필터)→가전 본체.

## 공지사항·필수 동의 (26-09-03)

구매대행·배송대행에서 실제로 분쟁이 되는 이슈를 `config/legal.js` 한 곳에
모았습니다. 공지 전문은 `/notice`, 접수 화면에서 6가지 필수 동의를 받고
**주문에 동의 시각과 항목을 기록**합니다(고지 이행 증빙).

| 분류 | 다루는 이슈 |
| --- | --- |
| 서비스의 성격 | 통신판매 당사자 아님(판매자 책임 구분), 검수 범위는 겉포장 |
| 요금 | 부피무게 청구, 실측 차액 정산(20,000동), 환율 고정 |
| 통관·세금 | 관·부가세 수하인 부담, 자가사용·재판매 금지, 수취인 정보 책임 |

## 쉬운 결제 화면 (26-09-03)

배송대행 이용이 많고, 10살 어린이·60세 어르신도 혼자 할 수 있어야 한다는
운영자 지시에 따라 결제 동선을 단순화했습니다.

- **결제 방법**: 드롭다운 → 국기와 큰 글씨의 **선택 카드 2장**(한국 원화 /
  베트남 동화). 고른 것은 파란 테두리와 ✓ 로 표시.
- **"이렇게 하시면 됩니다"**: 1·2·3 번호로 세 줄. 보낼 금액은 큰 빨간 글씨.
- **동의**: [모두 확인했습니다] 버튼 하나로 일괄 체크, 항목별 체크박스는
  22px 로 크게. 동의 전에는 주문 버튼이 눌리지 않고 이유를 버튼에 표시.
- **입금 화면**: 계좌번호를 24px 로 크게 보여주고 **누르면 복사**(복사됨
  피드백). 주문번호를 메모에 넣으라는 안내는 빨간 박스로 강조.

## 쿠팡 화면 변경 대응 (26-09-03)

쿠팡은 분기마다 화면을 손봅니다. 문구 하나가 바뀌면 확장의 배송지 자동
등록이 조용히 멈추고, 예전에는 고객 연락이 와야 알 수 있었습니다.
이제 **① 확장이 스스로 알리고 ② 서버에서 몇 분 만에 고칩니다.**

### ① 자가진단 — 고객보다 먼저 압니다

확장이 쿠팡 화면에서 찾아야 할 문구를 못 찾으면 서버로 조용히 보고합니다.
`/admin` 맨 위에 **「🩺 쿠팡 화면 점검」** 패널이 뜨면 그게 신호입니다.

| 표시 | 뜻 | 급한 정도 |
| --- | --- | --- |
| ⚡ 배송지 자동등록 실패 | 고객이 [자동 등록]을 눌렀는데 창을 못 찾음 | **가장 급함** — 지금 고객이 막혀 있습니다 |
| 🖥 결제 화면 문구 없음 | 결제 화면인데 [배송지 변경]·[결제하기]가 안 잡힘 | 급함 — 곧 위와 같은 일이 납니다 |
| 💰 결제 화면 금액을 못 읽음 | 상품·수량 표기가 바뀜 | 급함 — 견적 금액이 어긋날 수 있습니다 |

보고에는 **개인정보가 없습니다** — 어떤 문구가 몇 개 잡혔는지, 경로,
확장 버전뿐입니다 (`.data/coupang-health.jsonl`).

### ①-2 알림 — 관리자 화면을 안 봐도 옵니다

이상이 처음 잡히면 **그 자리에서 운영자에게 알림이 갑니다.** 화면을 열어볼
때까지 기다리지 않습니다.

* 보내는 곳: `NOTIFY_WEBHOOK_URL`(슬랙·디스코드·카카오워크 등) 과
  운영자 텔레그램 방(`TELEGRAM_OPERATOR_CHAT_ID`) — 주문 상태 알림과 같은 곳입니다.
  둘 다 없으면 `.data/operator-alerts.jsonl` 에 기록만 남습니다.
* **폰이 안 잠깁니다**: 같은 증상은 처음 즉시 한 번, 그 뒤로는 계속되는 동안
  1시간에 한 번(누적 횟수 포함). 전체로도 시간당 6건까지.
* 알림 문구에 **고치는 방법과 대상 항목이 함께** 옵니다.

```
🚨 쿠팡 화면 변경 의심 — ⚡ 배송지 자동등록 실패
못 찾은 것: 배송지 변경, 배송지 추가
위치: checkout.coupang.com/order/pc · 확장 v0.5.0 · 문구 설정 v1
방금 처음 발생 (2026. 9. 3. 오후 5:02)

고치는 법: config/coupang-patterns.js 의 openAddr, addAddr 에
새 문구를 추가하고 version 을 올린 뒤 서버 재시작 — 확장 재배포는 필요 없습니다.
```

### ② 고치는 법 — 확장 재배포 없이 5분

1. 실제 화면의 새 문구를 확인합니다.
   고객이 겪은 경우엔 카드의 **[🩺 진단 정보 복사]** 내용을 받아보세요.
2. `config/coupang-patterns.js` 의 해당 항목 뒤에 `|새문구` 를 붙입니다.
   **띄어쓰기는 빼고** 씁니다 (`받는 곳 변경` → `받는곳변경`).

   ```js
   openAddr: { source: '배송지변경|배송지선택|배송지수정|받는곳변경', maxLen: 12 },
   ```

3. 맨 위 `version` 을 1 올립니다.
4. 서버를 재시작합니다. 끝입니다 — **고객은 아무것도 안 해도 됩니다.**
   (확장은 설정을 6시간마다 받아오고, 확장을 🔄 새로고침하면 즉시 반영)

바꿀 수 있는 항목: `openAddr`(배송지 변경) · `addAddr`(배송지 추가) ·
`zipSearch`(우편번호 찾기) · `pick`(선택) · `payButton`(결제하기) ·
`zipSubmit`(주소 검색), 그리고 입력칸 셀렉터 `fields.name/phone/detail`.

### 안전장치 — 설정을 잘못 써도 서비스는 안 멈춥니다

* 서버 문구는 **더하기만** 합니다. 확장에 들어 있는 기본 문구는 그대로
  남아 함께 시도하므로, 오늘 되던 화면은 계속 됩니다.
* 서버가 죽어 있으면 기본 문구로 동작합니다.
* 위험한 정규식(`*` `+` `{n,}` 무한 반복, 300자 초과, 문법 오류)은
  확장이 채택하지 않습니다. 거부된 항목은 점검 패널에 표시됩니다.
* `npm test` 의 `coupang-patterns.test.js` 가 서버 설정이 확장 검사에
  통과하는지 미리 확인합니다 — **고치고 나서 `npm test` 한 번** 돌리세요.

### 월 1회 정기 점검 (5분)

쿠팡 화면이 조용히 바뀌었는데 아무도 안 걸린 상태를 막습니다.

1. 쿠팡에서 아무 상품이나 [바로구매] → 결제 화면까지 갑니다 (결제는 하지 않습니다).
2. 도우미 카드가 뜨고 **금액이 화면 금액과 같은지** 봅니다.
3. [⚡ 배송지 자동 등록]을 눌러 받는사람·전화·상세주소가 채워지는지 봅니다.
4. `/admin` 「🩺 쿠팡 화면 점검」이 비어 있는지 확인합니다.
5. 하나라도 어긋나면 위 ②의 절차로 문구를 추가합니다.
